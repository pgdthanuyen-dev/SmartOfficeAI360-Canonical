## Reading this matrix

This is an evidence inventory, not a delivery claim. `CODE_FACT` comes from the listed repository paths; `TEST_VERIFIED` names an existing focused test family; `LIVE_VERIFIED` is limited to the redacted R49 QLVB evidence recorded in current memory. `BUSINESS_CONFIRMED`, `HISTORICAL`, and `PLANNED` are labelled where used. No row claims a full-suite or whole-project pass.

Statuses are qualitative: `COMPLETE` requires current business, architecture, code/API, tests, operations, security, and appropriate live evidence. No subsystem meets that bar. `SUBSTANTIAL` has multiple maintained evidence types with explicit gaps; `PARTIAL` has bounded code/test evidence but material memory or operational gaps; `MINIMAL` has only a narrow entry; `PLANNED_ONLY` has no implementation evidence; `NOT_APPLICABLE` is used only when a coverage dimension cannot apply.
